### 原檔公式關鍵（B15:D22 逐列）

原檔每一列都係同一模式：**若該列用戶有輸入就直接採用，否則由支援表反算**：

```
B15 (乾球)  = IF(C9+C10+C11+C12=0,"-", IF(C9<>0, C9, <支援表反算>))
B16 (濕球)  = IF(..., IF(AND(C10<>0, C10>C9, C9<>0), "ERROR", IF(C10<>0, C10, <反算>)))
B17 (露點)  = IF(..., IF(C11<>0, C11, <反算>))
B18 (相對濕度) = IF(..., IF(C12<>0, C12, <反算>))   ← 只要有輸入就完全信任
B19 (比容)  = <支援表> ; B20 (密度) = 1/比容 ; B21 (含濕量) = <支援表> ; B22 (比焓) = <支援表>
```

## 二、發現嘅原檔問題

**原檔快取值本身就自相矛盾**：Air 2 輸入 乾球 10 ℃、濕球 9.6 ℃、相對濕度 **40 %**。
由 10/9.6 反算嘅相對濕度其實約 **95.2 %**（飽和邊緣）；由於 B18 一見 C12 有值就照抄，
表格顯示 40 % 而濕球仍係 9.6 ℃ —— 兩者物理上不可能同時成立。
（Air 1 嘅 24.6 ℃／19.2 ℃ → 60.57 % 就一致。）

→ App 唔應該照抄呢個行為。建議：**任何已輸入嘅值都顯示，但同時計出一致狀態，並在差異超過容差時
標示「輸入互相矛盾」**，讓用戶知道要刪邊一個（本模組現時已對 Air2 做同類標註）。

## 三、建議改法（照原檔排位、現代 UI）

1. **系統條件卡（照原檔 B5:C6）** — 海拔高度 + 大氣壓力；高度為主、壓力可手動覆寫（與第②頁轉輪頁同一套語意），
   並顯示 ISA 公式，壓力餵給全頁所有狀態。
2. **Air 1 ｜ Air 2 卡（照原檔 B8:D22）** — 完全照原檔排位：
   - 上半：4 列輸入（乾球／濕球／露點／相對濕度）× 2 欄；
   - 下半：8 列輸出（乾球／濕球／露點／相對濕度／比容／密度／含濕量／比焓）× 2 欄；
   - 輸入優先次序照原檔（有值就用），但**矛盾時顯示警示**並指出一致值；
   - 「濕球 > 乾球」時照原檔顯示 ERROR（並用文字說明）。
3. **濕空氣圖卡** — 保留現有互動圖（飽和線、Air1/Air2 兩點、可選過程線），壓力跟隨上面設定。
4. **摺疊保留** — 單狀態快速求解（四種配對）、混合（Mass Mixing）、盤管過程（Coil Process）共用同一壓力。
5. 刪除重複：現有「雙空氣比較」與新卡功能重疊，會被新卡取代。

**功能影響評估**：引擎不變（`psychro.js` 純函數）；新增海拔→壓力換算（與第②頁同一條 ISA 公式，
會抽成共用函數，避免兩處各寫一次）。輸入由「每欄 2 個」增至「每欄 4 個」但**唔會強迫填滿** ——
留空即由引擎反算，行為與原檔一致。

**驗收**：以原檔快取值逐格核對 Air 1（24.6／19.2 → 16.497 露點、60.566 %、0.8596 m³/kg、1.1634 kg/m³、
0.011721 kg/kg、54.583 kJ/kg）與 Air 2（10／9.6 → 0.8117、1.2320、0.0072624、28.354）；
矛盾偵測須對 Air 2 嘅 40 % 標示警示；跑 `npm run check` ＋ 瀏覽器實測 ＋ 截圖。

### 矛盾輸入處理（你選「兩者並示＋警示」）

- 輸入值**原樣保留**在輸入格（與原檔一致，方便對照）。
- 狀態由優先次序嘅獨立配對求解：(乾球,濕球) → (乾球,RH) → (乾球,露點) → (濕球,RH) → (露點,RH) → (濕球,露點)。
  `state()` 唔支援「濕球＋露點」，會先轉成「濕球＋含濕量」再求解。
- 任何**未參與該配對**嘅輸入值都會與推算值比較，相差超過容差（溫度 0.15 °C、RH 1.5 %）即標示
  「輸入互相矛盾 — 相對濕度：40 % vs 95.2 %」並提示刪去其中一項。
- 「濕球 > 乾球」照原檔 B16 規則標示 ERROR。
- **密度差異已註明**：原檔 B20 用 `1/比容`（1.1634 kg/m³，忽略水蒸氣質量）；本頁用 (1+W)/v
  （1.1770 kg/m³，正確濕空氣密度），兩者都寫入向量測試並在文件說明。
